# Extending the Project

This document describes how the `specs/` directory is organised, how its files map to pipeline stages, and how to add new agents or new code generation tools.

## 1. Files inside each specification folder

Some pipeline checks (lint, static analysis, graph evaluation) are generic across agents. Others — specification adherence, behavioral and trace checks — need per-agent artifacts that live inside the spec folder itself.

Each folder in `specs/` must therefore contain:

| File              | Description                                                                     | Used by stage |
|-------------------|---------------------------------------------------------------------------------|---------------|
| `spec.md`         | Human-authored specification of the agent (requirements, inputs, outputs, tools) | 01            |
| `spec_adherence.py` | Rubric used by the LLM-as-judge to score the agent against `spec.md`           | 05            |
| `test_deepeval.py` | Behavioral tests generated by `test_generator/blackbox_generator.py`           | 07            |
| `test_trace.py`    | Trajectory / trace tests generated by `test_generator/whitebox_generator.py`   | 08            |

Example layout:

```
specs/001_list_issues_agent/
├── spec.md
├── spec_adherence.py
├── test_deepeval.py
└── test_trace.py
```

Missing one of these files causes the corresponding stage to fail or be skipped.

## 2. Adding a new agent

1. Create a new folder under `specs/` using the naming convention `NNN_short_name` (e.g. `031_my_new_agent`).
2. Write `spec.md` following the template at `model/spec_model.md`.
3. Write `spec_adherence.py` with the acceptance criteria for the LLM judge (stage 05).
4. Generate the behavioral and trace test suites from `spec.md`:
   ```bash
   python3 test_generator/blackbox_generator.py specs/031_my_new_agent/spec.md
   python3 test_generator/whitebox_generator.py specs/031_my_new_agent/spec.md
   ```
5. Add `"031_my_new_agent"` to the `agents=(...)` array in `pipe.sh`.

## 3. Adding a new code generation tool

Adapters live in `pipeline/adapters/` and must subclass `BaseAdapter`:

```python
# pipeline/adapters/base_adapter.py
class BaseAdapter:
    def __init__(self, spec_path: Path, output_dir: Path):
        self.spec_file = Path(spec_path)
        self.output_dir = Path(output_dir)
        self.logs_dir = self.output_dir / "logs"
        self.logs_dir.mkdir(parents=True, exist_ok=True)

    def run(self):
        raise NotImplementedError
```

Steps:

1. **Install the CLI** for the new tool and make sure it is reachable on PATH.
2. **Create the adapter.** Add `pipeline/adapters/<new_tool>.py` implementing `run()`. The method should invoke the CLI with `self.spec_file` and leave the generated agent inside `self.output_dir`.
   ```python
   from pipeline.adapters.base_adapter import BaseAdapter

   class ExampleGenAdapter(BaseAdapter):
       def run(self):
           # call the external CLI, writing files inside self.output_dir
           ...
   ```
3. **Register the adapter** in `pipeline/01_generate.py`:
   ```python
   from adapters.example_gen import ExampleGenAdapter

   ADAPTERS = {
       "copilot": CopilotAdapter,
       "gemini": GeminiAdapter,
       "claude": ClaudeCodeAdapter,
       "codex": CodexAdapter,
       "opencode": OpenCodeAdapter,
       "example-gen": ExampleGenAdapter,
   }
   ```
4. **Wire it into `pipe.sh`** by adding the identifier to the `llms=(...)` array.
5. **Document the installation step** in `docs/usage.md`.
6. **Run the pipeline** end-to-end with the new tool to validate the integration.
