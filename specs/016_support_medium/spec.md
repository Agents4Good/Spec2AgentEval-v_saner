**Task:** você é um gerador de agentes de IA e abaixo está uma especificação de um agente. Gere um agente conforme a especificação. Considere que as ferramentas do agente devem ser geradas junto ao código do agente.  
**Contexto:** Um agente de IA é uma entidade que usa LLM e ferramentas para executar tarefas específicas de forma autônoma.  
**Output:** agent.py, requirements.txt, tests.py  
**Contrato de interface com o benchmark:**

| Requisito de interface | Exemplo |
| --- | --- |
| Modelo | GPT-4o |
| Framework | LangGraph |
| GenAI Tool | ChatOpenAI |
| Entrypoint | agent(query: str) |
| Output | str |

**Requisitos gerais:**

| Requisito | Significado | Especificação do agente | Critério de Corretude |
| --- | --- | --- | --- |
| Goal | Objetivo e comportamento principal do agente na voz ativa | O agente deve tratar solicitações de suporte ao cliente, lendo dinamicamente documentos fornecidos pelo usuário via URLs e/ou pesquisando na web pública. O agente deve analisar a intenção do usuário para selecionar autonomamente a(s) ferramenta(s) adequada(s), classificar a solicitação e sintetizar uma resposta fundamentada. | O comportamento principal está declarado definindo quem faz, o que faz e o resultado? |
| Persona (Opcional) | A personalidade que o agente assume ao realizar as tarefas | Agente de Suporte ao Cliente (Customer Support Agent) | A especificação define uma persona e sua área de atuação? A persona é adequada/coerente com o Goal? |
| Inputs | Informação enviada para o agente | `query`: Pergunta do cliente em linguagem natural (string), que pode conter solicitações diretas, dúvidas gerais/técnicas/faturamento ou URLs públicas diretas para documentos/logs. | A especificação define qual é a entrada esperada? |
| Tools | Lista com as ferramentas disponíveis e para que elas servem | T1 — `fetch_document(url: str)`: Busca documentos públicos via URLs diretas (utilizando a biblioteca `requests`) informadas pelo usuário na query, e retorna o texto bruto.<br><br>T2 — `search_web(query: str)`: Realiza pesquisas gerais na web utilizando a API do Tavily (`tavily-python`), e retorna o texto bruto. | A especificação define a ferramenta, seus parâmetros, o retorno e o **propósito de uso** dela estão definidos? |
| Constraints | Uma afirmação que restringe as ações que o agente (ou seus usuários/operadores) têm permissão de realizar. | C1 — O agente deve obter dados reais via APIs e ferramentas fornecidas, sendo proibida a fabricação de dados ou simulação de respostas.<br><br> C2 — O roteamento e seleção de ferramentas devem ser guiados dinamicamente pela LLM via prompt do sistema e definições de ferramentas. O agente não deve usar lógica procedural em Python para simular raciocínio.<br><br> C3 — O agente deve interromper a execução e não deve chamar nenhuma ferramenta quando a query estiver vazia, ofensiva ou sem sentido. <br><br>C4 — O agente deve capturar exceções em caso de falha de execução e o processo não deve travar.| A especificação declara explicitamente uma ação que o agente deve, não deve, ou só pode sob certas condições? A restrição está expressa em termos de ação/comportamento permitido ou proibido — não em termos de tecnologia, ferramenta ou biblioteca usada para implementar o agente? Quando a restrição envolve papel/autorização ("só X pode fazer Y"), a especificação define quem ou o que está autorizado? A restrição é verificável: é possível observar, no comportamento do agente, se ela foi violada ou respeitada? |
| Policies/Invariants | Afirmações que descrevem o que é verdadeiro sobre o domínio ou sobre o estado do agente em um dado momento | As respostas geradas devem ser estritamente fundamentadas na documentação recuperada.<br><br> A classificação da consulta deve pertencer obrigatoriamente a uma das três categorias: `Technical`, `Billing`, ou `General`.<br><br> O campo Tool deve listar as ferramentas([T1] e/ou [T2]) efetivamente invocadas para responder a consulta.<br><br> No campo `Documentation`, o texto bruto retornado pelas ferramentas deve ser copiado exatamente como recebido (sem parafrasear ou resumir) pelas ferramentas refletindo as fontes reais; caso nenhuma ferramenta retorne dados, deve ser preenchido com `"None"`. | A especificação declara uma relação, propriedade ou condição do domínio que é (ou deve ser) sempre verdadeira, e não uma ação permitida/proibida? O invariante está conectado a uma entrada, saída, evento ou dado que o agente efetivamente manipula (não é conhecimento de domínio irrelevante ao escopo do agente)? É possível verificar, a qualquer momento durante a execução, se o invariante ainda é válido? |
| Quality attributes (non-functional requirements) | Características observáveis do comportamento do agente durante a execução, que não descrevem o que ele faz nem o que ele nunca deve fazer, mas quão bem ele faz. | Não se aplica. | O atributo está descrito de forma observável/mensurável no comportamento? Existe um critério de aceitação verificável? Havendo trade-off entre atributos, a especificação deixa explícita a prioridade? |

| Comportamento | Input | Tools | Saída | Efeito no Ambiente | Condição de Satisfação |

| **B1 — Validar e filtrar consulta inválida** | Consulta vazia, altamente ofensiva ou irrelevante (sem sentido/gibberish). | Não se aplica. | String formatada iniciando com `Error: [clear explanation]`. | Não se aplica. | O agente interrompe o fluxo sem invocar ferramentas e retorna uma mensagem de erro clara. |
| **B2 — Processar consulta com URL direta** | Consulta em linguagem natural contendo URL pública para documento ou log. | [T1] | String formatada contendo os campos `Tool` (indicando [T1]), `Category`, `Documentation` e `Answer`. | Não se aplica. | A URL é extraída automaticamente pelo agente, e passada como parâmetro para [T1], o documento bruto é retornado em `Documentation` e a resposta é fundamentada nele. |
| **B3 — Buscar na web** | Consulta sobre integrações externas, problemas técnicos gerais ou faturamento/conta. | [T2] | String formatada contendo os campos `Tool` (indicando [T2]), `Category`, `Documentation` e `Answer`. | Não se aplica. | O agente seleciona [T2] pelo raciocínio sobre a query. As informações reais recuperadas alimentam o campo `Documentation` e fundamentam o campo `Answer`. |
| **B4 — Utilizar ambas as ferramentas** | Consulta que exige simultaneamente a leitura de URL direta e busca na web. | [T1] e [T2] | String formatada contendo os campos `Tool` (com ambas separadas por vírgula), `Category`, `Documentation` e `Answer`. | Não se aplica. | Ambas as ferramentas são executadas, e a saída reflete o uso das duas. |
| **B5 — Classificar a solicitação**| Documentação recuperada combinada e a consulta original.| Não se aplica. | Campo `Category` com exatamente uma das categorias: `Technical`, `Billing` ou `General`.| Não se aplica. | O agente classifica a solicitação em exatamente uma das três categorias.|
| **B6 — Sintetizar a resposta final**| Documentação recuperada combinada e a consulta original.| Não se aplica. | Resposta final que aborda diretamente a pergunta do usuário, estritamente fundamentada na documentação recuperada.| Não se aplica. | A resposta aborda diretamente a pergunta do usuário e é estritamente fundamentada na documentação recuperada.|
| **B7 — Nenhuma documentação encontrada** | Query válida para a qual a(s) ferramenta(s) não retornou(aram) nada (por exemplo, resultados de busca vazios).| [T1] e/ou [T2] | String formatada contendo os campos `Tool` (com uma ou ambas separadas por vírgula), `Category`, `Documentation` e `Answer`, com `Documentation: None`.| Não se aplica. | O campo `Documentation` exibe corretamente `"None"` e o agente não trava.|
| **B8 — Falha de execução**<br> | Consulta válida durante cuja execução ocorre uma falha (timeout, chaves de API ausentes ou exceção não tratada durante as chamadas de ferramentas).| [T1] e/ou [T2] | String de erro formatada começando com `Error: [Exception details]`.| Não se aplica. | O agente captura a exceção e retorna uma string de erro formatada começando com `Error: [Exception details]`; o processo não trava.|
| **B9 — Retornar resposta estruturada (Contrato de Saída)** | Consulta válida processada com sucesso. | Ferramenta(s) invocada(s) conforme a consulta, [T1] e/ou [T2]. | String estritamente no formato:<br><br>`Tool: [ferramenta(s)]`<br><br>`Category: [Technical, Billing ou General]`<br><br>`Documentation: [Texto bruto exato ou "None"]`<br><br>`Answer: [Resposta direta e fundamentada]` | Não se aplica. | A saída respeita integralmente o esquema de texto especificado. |
